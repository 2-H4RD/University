# Безопасный файловый менеджер: Python + PostgreSQL

Семестровое задание №1. Консольное приложение для работы с текстовыми,
JSON/XML-файлами и ZIP-архивами. Метаданные, пользователи и аудит хранятся
в PostgreSQL; содержимое — в объектном хранилище с AES-256-GCM.
Ключи и пароли подключения защищены Windows DPAPI и привязаны к текущему
профилю Windows. На диске D: используется exFAT: защита не полагается на
недоступные на нём NTFS ACL.

Исходные PDF и презентации в родительской папке не изменяются.

## Быстрый запуск на этом компьютере

Откройте PowerShell в папке проекта:

```powershell
Set-Location -LiteralPath 'D:\University\Проектирование и разработка безопасного программного обеспечения\Практики\Семестровое задание 1\secure_filemanager'
.\.venv\Scripts\python.exe -m filemanager --check
.\.venv\Scripts\python.exe -m filemanager
```

Можно также запускать `run.ps1`, `run.ps1 -Check` и
`run.ps1 -CreateAdmin`, если локальная политика PowerShell разрешает скрипты.
Менять глобальную политику выполнения не требуется.

На этом компьютере подготовлены `.venv`, рабочая БД `secure_filemanager`,
отдельная тестовая БД `secure_filemanager_test` и файлы подключения.
Пароль администратора PostgreSQL для обычного запуска не нужен.
Окружение создано на доступном Python 3.12.14 из локального runtime Codex;
системный Python 3.10 не изменён. Если базовый runtime будет удалён, пересоздайте
окружение на поддерживаемом Python 3.12+ по инструкции ниже.

### Первый администратор

```powershell
.\.venv\Scripts\python.exe -m filemanager --create-admin
```

Укажите собственные логин и пароль. Пароль не отображается; повторный запуск
не создаст второго администратора. Эта команда относится к доверенному
локальному развёртыванию. Внутри обычного меню выбора административной роли нет.
Универсального пароля приложения и заранее известного администратора нет.

### Первый сеанс

1. Запустите приложение, введите `register` и зарегистрируйте пользователя.
2. Введите `login` и войдите.
3. Введите `help`, чтобы посмотреть команды.
4. Создайте файл: `new "hello.txt" text`, затем введите содержимое.
5. Выполните `list`; скопируйте ID и версию файла.
6. Используйте `read ID`, `write ID 1`, затем `delete ID 2`.
7. Выполните `logout` или `exit`.

Логин: 3–32 символа, латинские буквы, цифры, точка, дефис, подчёркивание;
первый символ — буква или цифра. Регистр логина не различается.
Пароль: 15–128 символов, пробелы сохраняются. Команда `passwd` меняет пароль
и отзывает все ранее открытые сессии. Для смены требуется текущий пароль.

## Команды

| Команда | Назначение |
|---|---|
| `register`, `login`, `logout`, `passwd`, `whoami` | Учётные записи и сессия |
| `disks` | Диски, тип файловой системы, полный/занятый/свободный объём |
| `locations` | Персональные каталоги импорта и экспорта |
| `list` | Метаданные собственных файлов, ID и версии |
| `new "имя" text` | Создать текстовый файл |
| `new "имя.json" json` | Проверить и сохранить JSON |
| `new "имя.xml" xml` | Проверить и сохранить XML |
| `read ID` | Прочитать файл; вывод ограничен 64 КиБ |
| `write ID ВЕРСИЯ` | Заменить содержимое, сохраняя формат |
| `delete ID ВЕРСИЯ` | Удалить с проверкой версии |
| `import "имя" binary\|text\|json\|xml\|zip` | Импортировать из своего inbox |
| `export ID "имя"` | Экспортировать в свой outbox, без перезаписи |
| `zip "bundle.zip" ID1 ID2` | Создать ZIP |
| `zip-aes "secure.zip" ID1 ID2` | Создать ZIP AES-256 с паролем |
| `unzip ID "каталог"` | Извлечь в логический каталог |
| `unzip-aes ID "каталог"` | Извлечь зашифрованный ZIP |
| `audit 50`, `verify-audit` | Просмотр/проверка аудита администратором |
| `recover` | Очистка незавершённых объектов администратором |
| `disable-user ЛОГИН` | Деактивация пользователя администратором |

Команды разбираются как аргументы, не исполняются в оболочке ОС.
Имена с пробелами заключайте в двойные кавычки. Содержимое при создании/изменении
вводится одной строкой; многострочные и большие файлы импортируйте.
Пароли ZIP также запрашиваются скрыто.

### Импорт и экспорт

Выполните `locations`, скопируйте обычный файл в показанный inbox и введите,
например, `import "sample.json" json`. Примеры находятся в `examples/`.
Для вывода файла на диск используйте `export ID "result.json"`.

Каждому пользователю назначены собственные inbox/outbox с UUID в имени каталога.
Файлы приложения имеют логические имена, например `docs/readme.txt`;
физически содержимое хранится под случайными UUID.
Прямой ввод произвольного абсолютного пути для файловых операций запрещён.
Список дисков носит информационный характер и не открывает доступ ко всему диску.

Экспортированные копии и файлы, вручную помещённые в inbox, являются обычными
незашифрованными файлами. На exFAT их доступность определяется доступом к диску.
Внутренние objects всегда зашифрованы.
Экспорт не перезаписывает существующий файл. Для повторного экспорта выберите
другое имя или удалите старую экспортированную копию средствами ОС.
Квота учитывает активные файлы приложения и файлы в outbox.
Вручную помещённые в inbox файлы контролирует доверенный оператор Windows.

## Развёртывание с нуля

Требуется Windows 10/11, поддерживаемый Python 3.12+ и PostgreSQL 16.
Не удаляйте существующий `.venv` до установки подходящего Python.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock
.\.venv\Scripts\python.exe -m pip install -e . --no-deps --no-build-isolation
.\.venv\Scripts\python.exe scripts\bootstrap.py
.\.venv\Scripts\python.exe -m alembic upgrade head
$env:FM_ENV_FILE = '.env.test'
.\.venv\Scripts\python.exe -m alembic upgrade head
Remove-Item Env:FM_ENV_FILE
.\.venv\Scripts\python.exe -m filemanager --check
```

`bootstrap.py` скрыто запрашивает пароль локального `postgres`.
На текущем компьютере используйте предоставленный в задании пароль.
Скрипт создаёт только объекты проекта и не меняет чужие базы, системный пароль
PostgreSQL или глобальную конфигурацию сервера.
При наличии конфигурации повторный запуск сохраняет пароли.
Если БД/роли существуют, а файл конфигурации утрачен, скрипт остановится,
чтобы не присвоить себе существующие объекты и не сбросить чужие пароли.

Рабочая роль `fm_app` не является владельцем объектов. Отдельные
`fm_owner` и `fm_migrator` используются для владения и миграций.
Для тестов созданы независимые роли с префиксом `fm_test_`.
Пароли случайные, записаны в `.env` и `.env.test` в виде DPAPI ciphertext.
На NTFS дополнительно применяются ограниченные ACL; на exFAT они недоступны.
Не передавайте эти файлы вместе с исходниками.

Приложение разрешает только локальное подключение к БД.
Удалённое подключение требует отдельного проектирования TLS и модели доступа.

## Ограничения ресурсов

Значения по умолчанию; параметры можно задать в `.env` по именам из `.env.example`.

| Ограничение | Значение |
|---|---|
| Размер одного файла | 50 МиБ |
| Размер JSON/XML | 2 МиБ |
| Число узлов / глубина JSON/XML | 10000 / 32 |
| Атрибуты одного XML-элемента | 32 |
| Файлы/элементы в ZIP | 1000 |
| Суммарный размер извлечения ZIP | 200 МиБ |
| Коэффициент сжатия ZIP | 100:1 |
| Квота активных файлов и outbox пользователя | 1 ГиБ |
| Число активных файлов пользователя / outbox | 10000 / 1000 |
| Тайм-аут сессии по неактивности | 15 минут |
| Тайм-аут одной обработки документа/ZIP | 10 секунд |
| Память дочернего обработчика | 768 МиБ |
| Резерв свободного места перед записью | 64 МиБ |

Вложенные ZIP не распаковываются автоматически.
STORED и DEFLATE разрешены; другие методы сжатия отклоняются.
Даже самостоятельно созданный архив может не пройти последующее извлечение,
если его данные превышают политику коэффициента сжатия.
XML имеет произвольную корневую структуру в рамках указанных ограничений;
DTD, сущности, внешние ресурсы и XInclude запрещены.
JSON принимает объект или массив; дубли ключей и NaN/Infinity запрещены.
Никакие загруженные файлы автоматически не исполняются.

## Проверки

Не запускайте два набора интеграционных тестов одновременно: они используют
одну выделенную тестовую БД и сбрасывают её перед каждым тестом.
Рабочая БД тестами не очищается: имя и тестовая роль проверяются явно.

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.lock
.\.venv\Scripts\python.exe -m pytest --cov=filemanager --cov-report=term-missing --cov-report=xml:reports/coverage.xml --junitxml=reports/tests.xml
.\.venv\Scripts\python.exe -m ruff check src scripts tests migrations
.\.venv\Scripts\python.exe -m bandit -r src scripts -c pyproject.toml -f json -o reports/bandit.json
.\.venv\Scripts\python.exe scripts\scan_semgrep.py --self-test
.\.venv\Scripts\python.exe -m pip_audit --skip-editable --progress-spinner off --format json --output reports/pip-audit.json
```

Все проверки также собраны в `scripts/verify.ps1`.
Крупный нативный движок Semgrep хранится в Git LFS. После клонирования
репозитория установите Git LFS и получите файл движка из папки репозитория:

```powershell
git lfs install
git lfs pull
```

Перед запуском scripts/scan_semgrep.py проверяет SHA-256 движка и DLL по
сохранённому provenance.json. Python-обёртка Semgrep не требуется.

Semgrep запускается через комплектный официальный нативный движок с локальными
правилами, без Python-обёртки, отправки метрик и аккаунта. Перед запуском проверяются
SHA-256 движка и DLL; self-test подтверждает обнаружение опасного вызова.
pip-audit обращается к публичной базе уязвимостей, передавая названия и версии
зависимостей, не исходники и не конфигурацию БД.
Интеграционные тесты запускают реальные дочерние процессы, включая намеренное
аварийное завершение и проверку лимитов Windows Job Object.

Модель безопасности и восстановление: `docs/SECURITY.md`.
Фактические результаты проверки: `docs/VALIDATION.md`.

## Сбои и резервное копирование

При штатном запуске приложение проверяет цепочку аудита и очищает объекты,
которые не связаны с подтверждёнными метаданными. Активные записи не удаляются.
Администратор может повторить очистку командой `recover`.

На exFAT один нативный тест создания hardlink/junction пропускается: файловая система
не поддерживает эти объекты. Сам отказ по признакам открытого Win32 handle и
закрепление каталога проверяются отдельными тестами.

При ошибке после записи запрос мог завершиться до потери связи; после восстановления
сначала проверьте `list` и аудит. Не повторяйте вслепую операции изменения.
Отклонение старой версии означает, что нужно перечитать метаданные и содержимое.

Для согласованной резервной копии остановите все экземпляры приложения.
Сохраните дамп `secure_filemanager`, всё `var/`, `.env` и версии исходников.
Ключи `var/secrets/audit.key`, `var/secrets/storage.key` и checkpoint резервируются вместе с БД,
храниться с ограниченными правами и отдельно от публичного репозитория.
Миграционные пароли нужны только оператору развёртывания.
DPAPI-копии предназначены для восстановления под тем же профилем Windows.
Простое копирование папки другому пользователю или на другой компьютер не
переносит доступ к ключам; для этого нужна отдельная процедура переноса ключей.

Если проверка аудита сообщает `AUDIT_TAMPERED`, `AUDIT_CHECKPOINT_INVALID`
или `AUDIT_CHECKPOINT_MISSING`,
не удаляйте checkpoint и не создавайте новый ключ для обхода проверки.
Восстановите согласованный комплект БД/хранилища/ключа/checkpoint из доверенной
копии и расследуйте причину. Подробности границ защиты приведены в SECURITY.md.
