## Подготовка в Android Studio

1. File → Open → выберите эту папку Lesson8, дождитесь Gradle Sync. Встроенный Gradle JDK: Android Studio jbr. SDK: установленная платформа Android 35.
2. Device Manager → Pixel_9, Android 15/API 35 → Run. При зависшем снимке используйте Cold Boot, без удаления данных.
3. В списке Run выберите `Verify Lesson8`: это assembleDebug, lintDebug и testDebugUnitTest. Затем `Device Tests Lesson8` выполняет installDebug и :UITests:connectedDebugAndroidTest на реальном Android AVD. Не запускайте два набора UI одновременно на одном устройстве.
4. Для демонстрации отдельной программы выберите её Android App конфигурацию и Run. APK каждого модуля находится в build/outputs/apk/debug; MireaProject включён в общий проект и может открываться отдельно.
5. Build Success подтверждает сборку; успех демонстрации подтверждается действиями и результатами приложения. NO-SOURCE у JVM-тестов не считается выполненным практическим сценарием.

## Как читать проект

`settings.gradle.kts` включает модули. `applicationId` — пакет установленного APK; `namespace` — пакет R и Binding, они могут отличаться у снимков MireaProject. Manifest объявляет launcher, разрешения и компоненты. `res/layout` описывает View, `res/values` — строки и тему; ViewBinding генерирует ссылки по android:id. `MainActivity.onCreate` создаёт UI и callbacks. `BaseActivity.frame` учитывает системные Insets, `io` — Executor для долгой работы, `ui` доставляет изменение View в главный поток и проверяет актуальность Activity. `LabFragment` делает аналогичное для фрагмента и освобождает binding в onDestroyView. Сгенерированные Binding/R/Room-классы и каталоги build не являются вручную написанным предметным кодом.

Для каждого экрана на защите покажите цепочку: XML ID → поле binding/локальная переменная → слушатель кнопки → проверка данных → фоновая или системная операция → callback → видимый результат. Перед ответом о переменной найдите её объявление и все использования в Android Studio: Go to Declaration и Find Usages.

## YandexMaps · страницы PDF 9–14

**Задание:** MapKit, собственный API ключ, карта, lifecycle, runtime location, UserLocationLayer с pin/arrow/accuracy.

Добавьте личный MapKit mobile SDK key по ПОДКЛЮЧЕНИЕ_СЕРВИСОВ.md. MapKitFactory.setApiKey вызывается до initialize, карта — MapView с обязательными onStart/onStop вместе с MapKitFactory. Runtime ACCESS_FINE_LOCATION/COARSE_LOCATION выдаётся пользователем, layer = createUserLocationLayer(mapWindow). UserLocationObjectListener настраивает pin, arrow и accuracyCircle; сохраняйте сильную ссылку listener, иначе SDK может перестать доставлять события. Кнопка местоположения переносит камеру к актуальной точке. В отсутствие ключа показывается явная причина и действия не выдаются за работающую карту. В эмуляторе задайте GPS и покажите реальные тайлы и свой значок положения.

**Что предъявить:** Реальные тайлы и GPS после разрешения; корректный onStart/onStop. Сопоставьте с фактическим статусом в отчёте, не объявляйте недоступную интеграцию проверенной.

## YandexDriver · страницы PDF 15–18

**Задание:** Несколько вариантов маршрута от устройства до любимого заведения, GPS эмулятора, маркер с краткой информацией.

Начальная точка — последняя позиция устройства, конечная — выбранное заведение. Учебное заведение помечено как пример; свою точку можно ввести в полях. DrivingRouter COMBINED создаётся через DirectionsFactory, DrivingOptions запрашивает до трёх маршрутов. requestRoutes возвращает DrivingSession, listener получает настоящие DrivingRoute или ошибку. Каждый route.geometry рисуется своей Polyline, подпись содержит расстояние/время из metadata. Несколько вариантов возможны только если сервис их нашёл; код не выдумывает альтернативу прямым отрезком. Маркер назначения хранит описание и открывает диалог. Listener и session удерживаются полями; при повторном запросе старый session отменяется. Путь проверить можно только с действующим API ключом и сетью.

**Что предъявить:** Настоящие DrivingRoute от MapKit, несколько вариантов если сервис их возвращает, нажатие маркера. Сопоставьте с фактическим статусом в отчёте, не объявляйте недоступную интеграцию проверенной.

## OSMMaps · страницы PDF 19–23

**Задание:** osmdroid: тайлы, масштаб/жесты, камера, location, compass/rotation/scale, интересные места с описанием; два пункта/маршруты из условия раздела.

Configuration задаёт userAgentValue пакетом приложения, чтобы реальные tile-запросы были идентифицируемы. TileSourceFactory.MAPNIK — серверные тайлы, controller.setZoom/setCenter задают начальную камеру. MultiTouch/zoom buttons меняют масштаб; MyLocationNewOverlay использует Android location, CompassOverlay — направление, RotationGestureOverlay — поворот, ScaleBarOverlay — линейный масштаб. MapView.onResume/onPause управляют ресурсами. Marker содержит title/snippet и координаты GeoPoint. Два выбранных пункта передаются OSRM с lon,lat (внимание к порядку), alternatives=true просит реальные варианты; GeoJSON LineString преобразуется обратно в GeoPoint(lat,lon). Polyline показывает полученную геометрию, а не прямую. На защите нажмите маркер, приблизьте карту, передайте GPS, постройте маршрут и покажите фактический ответ либо ошибку сервиса.

**Что предъявить.** Откройте описание учебного маркера. Затем нажмите «Выбрать старт» и удерживайте точку на карте. Так же отметьте финиш, проверьте координаты A и B и нажмите «Построить маршруты». Покажите, как карта отображает ответ OSRM. Для демонстрации GPS отдельно откройте экран без ручного старта и нажмите «Моё местоположение». [Шаги и разбор OSMMaps](OSMMaps/README_ЗАЩИТА.md).

## MireaProject · страницы PDF 24

**Задание:** Фрагмент заведений, список/описания/карта; маркер показывает адрес+описание; дополнительная функция карты.

«Заведения» связывает список карточек и OSM карту. Встроенные точки — МИРЭА, парк Горького и Воробьёвы горы — явно учебные примеры. Нажатие карточки выбирает точку на карте, нажатие маркера показывает адрес и описание. Формой можно добавить собственное место с координатами и сохранить его в Preferences; проверяются пустые значения и диапазоны широты/долготы. Дополнительная функция fit bounds охватывает все точки, расстояние от устройства подписано как расстояние по прямой. Оно вычисляется отдельно от дорожного маршрута и не подменяет его. Для наследуемого Firebase-входа требуется собственный JSON либо явный локальный Auth Emulator; интеграции карты и входа имеют разные настройки.

**Что предъявить:** Карточки ↔ карта, маркер, пользовательское место, fit bounds и расстояние по прямой. Сопоставьте с фактическим статусом в отчёте, не объявляйте недоступную интеграцию проверенной.

## Ответы на общие вопросы

- **Почему не выполнять всё в onCreate/UI callback?** Главный поток обрабатывает ввод и кадры. Долгий I/O/ожидание задерживает интерфейс; отдельный Thread, Executor, Worker или асинхронный SDK отделяет ожидание, а результат возвращается в UI.
- **Почему нельзя хранить View навсегда?** Activity пересоздаётся при конфигурационных изменениях, View фрагмента уничтожается отдельно. Bundle/Preferences/Room/WorkManager хранят разные виды состояния; binding относится только к текущей View.
- **Что означает final?** Ссылку нельзя переназначить; состояние объекта по ней может изменяться. Значения, захватываемые лямбдой, должны быть final либо effectively final.
- **Что делает try-with-resources?** Гарантирует close для потока/Socket при нормальном выходе и исключении. finally используется для disconnect/восстановления кнопки.
- **Чем dp отличается от sp?** dp масштабирует размеры по плотности, sp дополнительно учитывает настройку размера шрифта. wrap_content измеряет содержимое, match_parent занимает доступную область, weight распределяет остаток.
- **Зачем проверять отказ/отмену/поворот?** Это обычные действия Android, а не редкие аварии. Код должен сохранить корректное состояние, показать причину и не подменять неудачу успехом.
- **Где результаты тестов?** В UITests/build/outputs/androidTest-results/connected/debug (JUnit XML), UITests/build/reports/androidTests/connected/debug (HTML), модульных build/reports/lint-results-debug.* и приложенных материалах verification. Скриншот подтверждает конкретный момент; assertion проверяет конкретное условие, ни один не доказывает всё приложение.
