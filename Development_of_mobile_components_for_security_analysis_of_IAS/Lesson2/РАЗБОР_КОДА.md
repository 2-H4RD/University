## Как связаны файлы и исполнение

1. settings.gradle.kts включает application-модули и репозитории. build.gradle.kts подключает плагин Android. Каталог libs.versions.toml связывает alias с координатами библиотек и версиями.
2. Android Studio запускает Gradle на встроенном JDK. Java sourceCompatibility=11 задаёт уровень исходного языка, а не путь/версию JVM, на которой работает Gradle. Gradle wrapper фиксирует воспроизводимую версию сборщика.
3. Модуль компилирует Java, ресурсы и manifest в отдельный APK. namespace определяет пакет сгенерированных R/Binding; applicationId определяет установленное приложение. Разные applicationId позволяют держать все учебные APK на одном устройстве.
4. Android находит launcher Activity через MAIN/LAUNCHER. ОС создаёт её экземпляр и вызывает onCreate. Приложение не создаёт Activity через new.
5. setContentView(R.layout...) либо Binding.inflate создаёт View из XML. После этого findViewById(R.id...) возвращает конкретный объект; имя R - сгенерированная ссылка на ресурс, а не путь к файлу.
6. Пользователь нажимает кнопку. Listener/метод android:onClick выполняется в главном потоке. Асинхронные ActivityResult, permission и WebView callbacks приходят позже; return в обработчике не отменяет уже запущенный внешний экран.

## Язык Java на примерах этой практики

`private` ограничивает доступ классом; `public` нужен внешнему вызову и android:onClick; отсутствие модификатора означает доступ внутри package. `static final` - общая неизменяемая константа класса; `private` поле живёт вместе с экземпляром Activity/Fragment. Локальная переменная существует в блоке метода/callback. Одинаковое имя в разных блоках не означает один объект.

`extends AppCompatActivity`/`Fragment` задаёт наследование. `@Override` проверяет переопределение метода родителя. `super` вызывает родительскую реализацию, необходимую для AndroidX состояния. `this` обозначает текущий объект и также служит Context для Activity. Приведение `(TextView)` уточняет тип View; в этой версии findViewById обычно использует вывод типа.

`view -> ...` - lambda, реализующая один метод listener; `this::method` - ссылка на готовый метод подходящей сигнатуры. Код lambda исполняется по событию, а не сразу при setOnClickListener. Цепочка Builder возвращает builder после каждого set, завершаясь build/create. Тернарный `condition ? a : b` выбирает одно значение. `&&` проверяет правую часть только при истинной левой: проверка null/length защищает последующий доступ. `try/catch` обрабатывает конкретную ожидаемую ошибку.

`String` - текст; `int` - целое (код, ID, количество); `long` - миллисекунды времени; `boolean` - состояние; `Bundle` - пары ключ/значение; `Intent` - запрос запуска/контейнер результата; `Uri` - структурированный адрес; `Bitmap` - пиксельное изображение. ID ресурса int, тег фрагмента String, имя extra String и номер уведомления int решают разные задачи и не взаимозаменяемы.

## Отступы, ориентация и состояние

Поворот обычно уничтожает старую Activity и создаёт новую, автоматически выбирая layout-land. Поэтому ссылка на прежний View не является сохранённым состоянием. EditText и CheckBox с стабильными ID Android сохраняет автоматически; вычисленный результат TextView сохраняется явно в Bundle. После Home существующий экземпляр может остаться, но система вправе уничтожить процесс. Bundle не гарантирует сохранность данных после force-stop/новой установки и не является базой данных.

EdgeToEdge разрешает рисовать под системными панелями. Insets сообщают их размеры и область клавиатуры. Исходный padding запоминается до назначения listener; каждый callback вычисляет padding заново от исходного значения. Суммировать прошлый padding с новыми Insets нельзя: отступ будет нарастать. Для пересекающихся нижних областей используются максимум/объединение типов.

**onCreate (строка 33).** Android вызывает метод для нового экземпляра. savedInstanceState - Bundle предыдущего состояния или null при первом создании. Сначала super, затем загрузка XML/Binding, затем поиск элементов и регистрация действий. Это не функция, вызываемая кнопкой.

**onStart (строка 44).** Экран становится видимым. super сохраняет поведение AndroidX; Log.i выводит событие с TAG. Повторный onStart не обязательно означает новый onCreate.

**onResume (строка 54).** Activity готова взаимодействовать с пользователем. После возврата на существующий экран callback вызывается снова. Здесь не следует заново стирать содержимое EditText.

**onPause (строка 64).** Activity теряет активное состояние. Она может ещё быть видна. Callback не равен закрытию приложения и не гарантирует последующий onDestroy.

**onStop (строка 73).** Activity больше не видна. Существующий экземпляр может остаться в памяти и вернуться через onRestart.

**onRestart (строка 82).** Возвращается остановленный существующий экземпляр; дальше идут onStart и onResume. При новом экземпляре вместо этого вызывается onCreate.

**onDestroy (строка 92).** Завершает текущий экземпляр. Поворот тоже может вызвать уничтожение/создание Activity. При уничтожении процесса системой callback не гарантируется.

**onSaveInstanceState (строка 102).** outState - Bundle для компактных значений UI. putString/putParcelable связывают ключ и значение. super позволяет Android сохранить View с ID и состояние FragmentManager. Это не постоянное хранилище и не замена файлу/базе данных.

**onRestoreInstanceState (строка 111).** state содержит ранее сохранённые значения. Родитель восстанавливает View по их ID. Метод вызывается после onStart только при наличии сохранённого состояния.

**applyInsets (строка 121).** root - корневой View; left/top/right/bottom - исходный padding XML. bars - системные панели, ime - клавиатура. Listener прибавляет Insets к исходным отступам, поэтому повторное событие не увеличивает padding бесконечно. max выбирает нижнюю неперекрываемую область.

**onCreate (строка 34).** Android вызывает метод для нового экземпляра. savedInstanceState - Bundle предыдущего состояния или null при первом создании. Сначала super, затем загрузка XML/Binding, затем поиск элементов и регистрация действий. Это не функция, вызываемая кнопкой.

**onClickShowTime (строка 52).** Создаёт фрагмент штатного TimePickerDialog. Тег time отличает его от других диалогов.

**onClickShowDate (строка 58).** Создаёт фрагмент DatePickerDialog с тегом date. Дата задаётся Calendar устройства и возвращается listener.

**onClickShowProgress (строка 64).** Создаёт учебный ProgressDialog. Вращение не отражает реальную сетевую работу; закрытие выполняет пользователь.

**showOnce (строка 71).** dialog - новый DialogFragment, tag - его строковое имя в FragmentManager. findFragmentByTag предотвращает повторный показ уже открытого окна. DialogFragment поддерживает восстановление при повороте.

**onOkClicked (строка 79).** Вызывает showChoice с ресурсом положительного ответа «Иду дальше». Этот callback связан с setPositiveButton.

**onNeutralClicked (строка 84).** Вызывает showChoice с ответом «На паузе». Порядок отображения кнопок задаёт тема, а не имя метода.

**onCancelClicked (строка 90).** Вызывает showChoice с отрицательным ответом «Нет». Это выбор кнопки диалога, а не отмена Activity Result.

**showChoice (строка 96).** messageId - целочисленный ID строкового ресурса. getString превращает его в String message. TextView result и Toast показывают одинаковый ответ.

**onTimeSelected (строка 104).** hour и minute - значения TimePicker. getString форматирует оба числа; шаблон %02d дополняет число ведущим нулём.

**onDateSelected (строка 110).** year/month/day приходят от DatePicker. month имеет диапазон 0..11; +1 выполняется только для понятного пользователю отображения.

**showPickerResult (строка 116).** text - уже отформатированный результат. TextView оставляет его на экране, Snackbar показывает короткое уведомление внизу текущего View.

**onSaveInstanceState (строка 125).** outState - Bundle для компактных значений UI. putString/putParcelable связывают ключ и значение. super позволяет Android сохранить View с ID и состояние FragmentManager. Это не постоянное хранилище и не замена файлу/базе данных.

**applyInsets (строка 135).** root - корневой View; left/top/right/bottom - исходный padding XML. bars - системные панели, ime - клавиатура. Listener прибавляет Insets к исходным отступам, поэтому повторное событие не увеличивает padding бесконечно. max выбирает нижнюю неперекрываемую область.

**onCreate (строка 31).** Android вызывает метод для нового экземпляра. savedInstanceState - Bundle предыдущего состояния или null при первом создании. Сначала super, затем загрузка XML/Binding, затем поиск элементов и регистрация действий. Это не функция, вызываемая кнопкой.

**onClickOpenBrowser (строка 42).** Создаёт URI веб-страницы и неявный Intent ACTION_VIEW. Адрес обработчика не задан: его выбирает ОС. HTTPS использует защищённое соединение.

**onClickShare (строка 52).** Создаёт ACTION_SEND и MIME text/plain. EXTRA_TEXT - содержимое, EXTRA_SUBJECT - тема. createChooser принудительно предлагает список подходящих получателей. Выполнение startActivity ещё не означает фактическую отправку адресату.

**launchSafely (строка 63).** intent - полностью подготовленный запрос. try выполняет startActivity; catch обрабатывает отсутствие подходящей Activity. Исключение нельзя считать успешным выполнением задания.

**applyInsets (строка 76).** root - корневой View; left/top/right/bottom - исходный padding XML. bars - системные панели, ime - клавиатура. Listener прибавляет Insets к исходным отступам, поэтому повторное событие не увеличивает padding бесконечно. max выбирает нижнюю неперекрываемую область.

**onCreate (строка 35).** Android вызывает метод для нового экземпляра. savedInstanceState - Bundle предыдущего состояния или null при первом создании. Сначала super, затем загрузка XML/Binding, затем поиск элементов и регистрация действий. Это не функция, вызываемая кнопкой.

**onClickNewActivity (строка 47).** view - нажатая кнопка из android:onClick. input ссылается на EditText. intent адресует SecondActivity; EXTRA_TEXT согласовывает имя extra. startActivity отправляет запрос Android, а не вызывает Java-конструктор Activity вручную.

**onStart (строка 57).** Экран становится видимым. super сохраняет поведение AndroidX; Log.i выводит событие с TAG. Повторный onStart не обязательно означает новый onCreate.

**onResume (строка 66).** Activity готова взаимодействовать с пользователем. После возврата на существующий экран callback вызывается снова. Здесь не следует заново стирать содержимое EditText.

**onPause (строка 75).** Activity теряет активное состояние. Она может ещё быть видна. Callback не равен закрытию приложения и не гарантирует последующий onDestroy.

**onStop (строка 84).** Activity больше не видна. Существующий экземпляр может остаться в памяти и вернуться через onRestart.

**onRestart (строка 93).** Возвращается остановленный существующий экземпляр; дальше идут onStart и onResume. При новом экземпляре вместо этого вызывается onCreate.

**onDestroy (строка 102).** Завершает текущий экземпляр. Поворот тоже может вызвать уничтожение/создание Activity. При уничтожении процесса системой callback не гарантируется.

**onSaveInstanceState (строка 112).** outState - Bundle для компактных значений UI. putString/putParcelable связывают ключ и значение. super позволяет Android сохранить View с ID и состояние FragmentManager. Это не постоянное хранилище и не замена файлу/базе данных.

**onRestoreInstanceState (строка 121).** state содержит ранее сохранённые значения. Родитель восстанавливает View по их ID. Метод вызывается после onStart только при наличии сохранённого состояния.

**applyInsets (строка 131).** root - корневой View; left/top/right/bottom - исходный padding XML. bars - системные панели, ime - клавиатура. Listener прибавляет Insets к исходным отступам, поэтому повторное событие не увеличивает padding бесконечно. max выбирает нижнюю неперекрываемую область.

**onRestart (строка 91).** Возвращается остановленный существующий экземпляр; дальше идут onStart и onResume. При новом экземпляре вместо этого вызывается onCreate.

**onDestroy (строка 100).** Завершает текущий экземпляр. Поворот тоже может вызвать уничтожение/создание Activity. При уничтожении процесса системой callback не гарантируется.

**onSaveInstanceState (строка 110).** outState - Bundle для компактных значений UI. putString/putParcelable связывают ключ и значение. super позволяет Android сохранить View с ID и состояние FragmentManager. Это не постоянное хранилище и не замена файлу/базе данных.

**onRestoreInstanceState (строка 119).** state содержит ранее сохранённые значения. Родитель восстанавливает View по их ID. Метод вызывается после onStart только при наличии сохранённого состояния.

**applyInsets (строка 129).** root - корневой View; left/top/right/bottom - исходный padding XML. bars - системные панели, ime - клавиатура. Listener прибавляет Insets к исходным отступам, поэтому повторное событие не увеличивает padding бесконечно. max выбирает нижнюю неперекрываемую область.

**onCreate (строка 45).** Android вызывает метод для нового экземпляра. savedInstanceState - Bundle предыдущего состояния или null при первом создании. Сначала super, затем загрузка XML/Binding, затем поиск элементов и регистрация действий. Это не функция, вызываемая кнопкой.

**applyInsets (строка 124).** root - корневой View; left/top/right/bottom - исходный padding XML. bars - системные панели, ime - клавиатура. Listener прибавляет Insets к исходным отступам, поэтому повторное событие не увеличивает padding бесконечно. max выбирает нижнюю неперекрываемую область.

## Частые вопросы преподавателя

- Почему Java нельзя найти View до setContentView? Иерархия ещё не создана, поэтому получим null и возможный NullPointerException.
- Чем ресурс отличается от строки? R.string/R.id/R.layout - числовые идентификаторы; getString получает текст по ID, setContentView загружает XML по ID.
- Почему есть проверки null? При отмене/отсутствующем extra Intent и его значения могут отсутствовать. Это обычное условие, а не обязательно ошибка пользователя.
- Что изменится при повороте? Меняется экземпляр Activity и XML квалификатор; компактное состояние восстанавливается по Bundle/ID. Сохранённая ссылка на старую View не заменяет сохранение значения.
- Чем явный Intent отличается от неявного? Явный содержит класс Activity, неявный - действие/data/MIME; выбор обработчика делает Android по manifest-фильтрам.
- Почему finish не равно setResult? setResult готовит ответ, finish завершает второй экран; для возврата пользовательских данных нужны оба действия.
- Где менять данные студента и подписи? В соответствующих strings.xml/константах, а не в сгенерированном R или build. В IntentApp номер задаётся STUDENT_NUMBER.
- Как подтвердить выполнение? Показать требование PDF, участок Java, связанный XML и действие на запущенном APK; отдельно назвать границы проведённой проверки.
