## Подготовка в Android Studio

1. File → Open → выберите эту папку Lesson6, дождитесь Gradle Sync. Встроенный Gradle JDK: Android Studio jbr. SDK: установленная платформа Android 35.
2. Device Manager → Pixel_9, Android 15/API 35 → Run. При зависшем снимке используйте Cold Boot, без удаления данных.
3. В списке Run выберите `Verify Lesson6`: это assembleDebug, lintDebug и testDebugUnitTest. Затем `Device Tests Lesson6` выполняет installDebug и :UITests:connectedDebugAndroidTest на реальном Android AVD. Не запускайте два набора UI одновременно на одном устройстве.
4. Для демонстрации отдельной программы выберите её Android App конфигурацию и Run. APK каждого модуля находится в build/outputs/apk/debug; MireaProject включён в общий проект и может открываться отдельно.
5. Build Success подтверждает сборку; успех демонстрации подтверждается действиями и результатами приложения. NO-SOURCE у JVM-тестов не считается выполненным практическим сценарием.

## Как читать проект

`settings.gradle.kts` включает модули. `applicationId` — пакет установленного APK; `namespace` — пакет R и Binding, они могут отличаться у снимков MireaProject. Manifest объявляет launcher, разрешения и компоненты. `res/layout` описывает View, `res/values` — строки и тему; ViewBinding генерирует ссылки по android:id. `MainActivity.onCreate` создаёт UI и callbacks. `BaseActivity.frame` учитывает системные Insets, `io` — Executor для долгой работы, `ui` доставляет изменение View в главный поток и проверяет актуальность Activity. `LabFragment` делает аналогичное для фрагмента и освобождает binding в onDestroyView. Сгенерированные Binding/R/Room-классы и каталоги build не являются вручную написанным предметным кодом.

Для каждого экрана на защите покажите цепочку: XML ID → поле binding/локальная переменная → слушатель кнопки → проверка данных → фоновая или системная операция → callback → видимый результат. Перед ответом о переменной найдите её объявление и все использования в Android Studio: Go to Declaration и Find Usages.

## app · страницы PDF 3–5

## SecureSharedPreferences · страницы PDF 5–7

**Задание:** Любимый поэт и изображение/рисунок; EncryptedSharedPreferences; скрин шифрованного XML в raw.

Методичка в тексте просит любимого поэта с изображением, а пример кода упоминает актёра: основной поэт и дополнительный actor реализованы одновременно. Выберите изображение через OpenDocument; takePersistableUriPermission сохраняет право чтения при перезапуске, portrait хранит android.resource:// URI встроенного изображения либо content:// URI выбранного файла, а не сами пиксели. MasterKey AES256_GCM создаёт ключ в AndroidKeyStore. EncryptedSharedPreferences использует AES256_SIV для имён ключей и AES256_GCM для значений. POET/ACTOR/PORTRAIT записываются в secret_shared_prefs; сохранение без поэта/портрета отклоняется. Инициализация и commit идут в io, затем ui обновляет поля. Покажите восстановление и Device Explorer: имя не должно лежать открытым текстом в XML. Служебные keyset-записи ожидаемы. Этот API оставлен по прямому требованию PDF; его устаревание объясните отдельно от принципа Keystore. Не переносите шифрованный XML на другое устройство без ключа.

**Что предъявить:** Успешная запись/чтение после рестарта; отсутствие открытого имени в XML. Сопоставьте с фактическим статусом в отчёте, не объявляйте недоступную интеграцию проверенной.

## EmployeeDB · страницы PDF 15–24

**Задание:** Room: Entity/DAO/Database/Application, вымышленные супергерои, CRUD.

ID героя пользователь вводит вручную. @PrimaryKey обеспечивает уникальность, INSERT IGNORE возвращает -1 при конфликте и сохраняет прежнюю запись. Проверки идут по порядку: пустое поле → целое число long → больше нуля → свободный ID. Причина отказа видна рядом с ID и в области результата. App создаёт один объект Room на процесс, запросы выполняются в io, результат возвращается через ui. Для защиты покажите все ошибки, добавление ID 42, отказ повторной вставки 42, изменение, перезапуск, удаление и повторное использование 42.

## Ответы на общие вопросы

- **Почему не выполнять всё в onCreate/UI callback?** Главный поток обрабатывает ввод и кадры. Долгий I/O/ожидание задерживает интерфейс; отдельный Thread, Executor, Worker или асинхронный SDK отделяет ожидание, а результат возвращается в UI.
- **Почему нельзя хранить View навсегда?** Activity пересоздаётся при конфигурационных изменениях, View фрагмента уничтожается отдельно. Bundle/Preferences/Room/WorkManager хранят разные виды состояния; binding относится только к текущей View.
- **Что означает final?** Ссылку нельзя переназначить; состояние объекта по ней может изменяться. Значения, захватываемые лямбдой, должны быть final либо effectively final.
- **Что делает try-with-resources?** Гарантирует close для потока/Socket при нормальном выходе и исключении. finally используется для disconnect/восстановления кнопки.
- **Чем dp отличается от sp?** dp масштабирует размеры по плотности, sp дополнительно учитывает настройку размера шрифта. wrap_content измеряет содержимое, match_parent занимает доступную область, weight распределяет остаток.
- **Зачем проверять отказ/отмену/поворот?** Это обычные действия Android, а не редкие аварии. Код должен сохранить корректное состояние, показать причину и не подменять неудачу успехом.
- **Где результаты тестов?** В UITests/build/outputs/androidTest-results/connected/debug (JUnit XML), UITests/build/reports/androidTests/connected/debug (HTML), модульных build/reports/lint-results-debug.* и приложенных материалах verification. Скриншот подтверждает конкретный момент; assertion проверяет конкретное условие, ни один не доказывает всё приложение.

## Личный выбор пользователя

Сериал — **«Лучше звоните Солу»**, выбран в ответе пользователя. В app это начальное значение MOVIE; прежняя техническая строка Training film заменяется только в отображении, а другой сохранённый ввод имеет приоритет. Кнопка сохранения записывает фактическое поле через Editor.commit.

Поэт — **Пушкин Александр Сергеевич**. [Портрет из ответа пользователя](SecureSharedPreferences/src/main/res/drawable/pushkin_portrait.jpg) сохранён без изменения JPEG (192×148, 4171 байт). Ресурс находится в SecureSharedPreferences/src/main/res/drawable и открывается через Android Studio. DEFAULT_POET задаёт только начальное имя, previousFixture распознаёт старую учебную заглушку; собственные сохранённые имена/фотографии не удаляются. Начальный URI android.resource://<applicationId>/drawable/pushkin_portrait ссылается на ресурс внутри APK, поэтому интернет/SAF для первого показа не нужны. Кнопка выбора всё ещё открывает системный OpenDocument: новый content:// URI получает сохраняемое право чтения. save записывает POET/ACTOR/PORTRAIT в EncryptedSharedPreferences; после force-stop читаются те же значения. **JPEG внутри APK не шифруется**: шифруются значения настроек, включая ссылку на портрет.
