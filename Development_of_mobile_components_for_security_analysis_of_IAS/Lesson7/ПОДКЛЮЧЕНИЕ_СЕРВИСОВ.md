# Подключение личных сервисов

## Firebase Email/Password

1. В собственной [Firebase Console](https://console.firebase.google.com/) создайте/выберите проект. Authentication → Sign-in method → Email/Password → Enable.
2. Project settings → Your apps → Add Android app. Для отдельного упражнения Lesson7 пакет `ru.mirea.ZubarevVS.lesson7.firebaseauth`; для общего приложения Lesson7/8 — `ru.mirea.ZubarevVS.mireaproject`. Это два Android-клиента одного выбранного проекта либо осознанно разных проектов.
3. Скачайте соответствующие `google-services.json`. Положите файл упражнения в `Lesson7/FirebaseAuth/google-services.json`, общего приложения в `Lesson7/MireaProject/app/google-services.json`; для Lesson8 скопируйте JSON того же общего applicationId в `Lesson8/MireaProject/app/google-services.json`.
4. В Android Studio: Sync Project with Gradle Files → Verify → Run. Условное применение стандартного google-services плагина подключит ресурсы. Не меняйте namespace на package из случайного чужого JSON и не подставляйте чужие ключи.
5. Создайте собственный тестовый email/password аккаунт в приложении, отправьте письмо проверки, откройте ссылку самостоятельно и обновите статус в приложении. Выйдите и войдите снова. UID сверяйте с Authentication → Users. Сделайте реальные скрины приложения и консоли; поместите их в соответствующий `src/main/res/raw` с именами только из a-z0-9_ (например `firebase_user_app.png`, `firebase_console_user.png`). Секрет пароля в скриншот не включайте.
6. Аккаунт Google/почту авторизует сам владелец. Без JSON и включённого провайдера облачную регистрацию и письмо проверить нельзя. Debug APK с пустой конфигурацией показывает это явно.

Официальное описание: [Firebase Android setup](https://firebase.google.com/docs/android/setup), [Password Authentication](https://firebase.google.com/docs/auth/android/password-auth).

## Необязательный официальный Auth Emulator

Код поддерживает `-PfirebaseEmulatorHost=10.0.2.2` только для debug, порт 9099, projectId `demo-mirea-labs`. Это явная настройка Gradle, а не автоматическое переключение при ошибке облака. Нужен отдельно запущенный официальный Firebase Local Emulator Suite на компьютере. Настройку и его фактическую установленность смотрите в отчёте: наличие ветки кода само по себе не означает, что Emulator установлен/проверен. Локальный UID и локальная ссылка проверки не являются доказательством облачной консоли из PDF. После локальной проверки уберите параметр, пересоберите и проверяйте собственный облачный проект. Документация: [Connect Auth Emulator](https://firebase.google.com/docs/emulator-suite/connect_auth).

## Практика 7: материалы для сдачи

Для практики создан проект [MIREA Lesson 7](https://console.firebase.google.com/project/mirea-lesson-7/settings/general) с ID `mirea-lesson-7`. Оба Android-приложения из таблицы зарегистрированы, Email/Password включён. В разделе **Project settings → General → Your apps** по очереди выберите **FirebaseAuth** и **MireaProject**, нажимая **Download google-services.json** для каждого приложения.

Оба файла уже размещены в модулях этого экземпляра `Lesson7`, сборки установлены на **Pixel 9 Lesson7**. На этом компьютере можно сразу начать с раздела «Получить два обязательных скриншота FirebaseAuth». Шаги скачивания пригодятся при переносе проекта или замене конфигурации.

### 1. Зарегистрировать два Android-приложения в Firebase

1. Откройте [Firebase Console](https://console.firebase.google.com/) и войдите в свой Google-аккаунт. Выберите свой учебный проект или создайте новый. Для задания достаточно одного проекта Firebase с двумя Android-приложениями.
2. Откройте **Authentication → Sign-in method → Email/Password**. Если раздел ещё не настроен, сначала нажмите **Get started**. Включите обычный вход по почте и паролю и сохраните настройку.
3. В **Project settings → General → Your apps** добавьте Android-приложения. Введите имена пакетов с тем же регистром символов, что в таблице.

| Конфигурация запуска Android Studio | Android package name в Firebase | Куда положить файл |
|---|---|---|
| FirebaseAuth | `ru.mirea.ZubarevVS.lesson7.firebaseauth` | `Lesson7/FirebaseAuth/google-services.json` |
| MireaProject | `ru.mirea.ZubarevVS.mireaproject` | `Lesson7/MireaProject/app/google-services.json` |

4. Скачайте конфигурацию для каждого клиента и положите её рядом с `build.gradle.kts` соответствующего модуля. Если браузер сохранил файл с суффиксом `(1)`, при размещении верните имя `google-services.json`. При ошибке `No matching client found for package name` проверьте `client_info.android_client_info.package_name` в JSON и имя пакета из таблицы.
5. Откройте **Lesson7** в Android Studio. Запустите **File → Sync Project with Gradle Files**, затем конфигурацию **Verify Lesson7**. Gradle-плагин и Firebase SDK уже указаны в проекте. Для облачной проверки уберите параметр `firebaseEmulatorHost`, если его устанавливали ранее.
6. В **Device Manager** запустите **Pixel 9 Lesson7** и выберите его рядом с кнопкой Run. У практик 7 и 8 один `applicationId` у MireaProject. Если на устройстве уже установлена практика 8, установка практики 7 может завершиться ошибкой `INSTALL_FAILED_VERSION_DOWNGRADE`. Отдельный эмулятор позволяет проверять обе версии.

### 2. Получить два обязательных скриншота FirebaseAuth

1. В выпадающем списке рядом с Run выберите **FirebaseAuth** и запустите его. На экране должны быть доступны поля Email и пароля и кнопка **Создать пользователя**.
2. Введите адрес тестового ящика, который вы можете открыть, и отдельный пароль длиной от шести символов или длиннее, если в проекте установлена более строгая политика. Нажмите **Создать пользователя**. На экране появятся Email, UID и статус подтверждения.
3. Нажмите **Отправить письмо проверки**. Откройте письмо в тестовом ящике и перейдите по ссылке. Вернитесь в приложение и нажмите **Обновить статус почты**. Проверьте, что отображается `Почта подтверждена: true`.
4. Нажмите **Выйти**, убедитесь, что форма входа вернулась, и снова войдите под тем же тестовым пользователем. Сравните UID до выхода и после входа.
5. Сделайте снимок экрана приложения с читаемыми Email, UID и статусом подтверждения. В Android Studio откройте **Running Devices**, выберите Pixel 9 Lesson7 и нажмите кнопку **Take Screenshot** с иконкой камеры на панели эмулятора. Сохраните PNG под именем `firebase_user_app.png`.
6. В том же Firebase-проекте откройте **Authentication → Users**. Найдите тестовый Email и сверяйте UID этой строки с UID на экране приложения. Снимите окно браузера так, чтобы были видны раздел **Users**, Email и UID. Сохраните как `firebase_console_user.png`.
7. Создайте папку `Lesson7/FirebaseAuth/src/main/res/raw` и положите туда оба PNG. В Android Studio переключите левое дерево на **Project**, чтобы проверить физический путь. Откройте оба PNG и убедитесь, что Email и UID читаются. Пароль, письмо со ссылкой подтверждения и данные других аккаунтов для этих двух снимков не нужны.

Итоговые пути:

```text
Lesson7/FirebaseAuth/src/main/res/raw/firebase_user_app.png
Lesson7/FirebaseAuth/src/main/res/raw/firebase_console_user.png
```

### 3. Подготовить демонстрацию сетевых упражнений

- **TimeService.** Выберите одноимённую конфигурацию и нажмите **Получить время по Socket :13**. На снимке для отчёта оставьте отдельные поля даты и времени UTC, исходную строку `UTC(NIST)` и статус подключения. Если порт 13 недоступен в выбранной сети, сохраните сообщение об ошибке отдельно и повторите проверку из сети с доступом к порту 13.
- **HttpURLConnection.** Выберите одноимённую конфигурацию и нажмите **Определить IP и погоду**. Снимите экран с внешним IP, городом, регионом, страной, координатами и погодой. Для защиты покажите в `MainActivity`, что координаты из ответа IP-сервиса подставляются в запрос Open-Meteo.
- **MireaProject.** Запустите конфигурацию **MireaProject** на Pixel 9 Lesson7. Если оба приложения подключены к одному Firebase-проекту, войдите с тем же тестовым Email и паролем. Снимите главный экран после входа, откройте через меню **Сетевой ресурс**, нажмите **Обновить погоду** и снимите результат. Через **Аккаунт** выйдите из сессии и проверьте, что кнопка «Назад» не открывает закрытый главный экран.
- Снимки сети и MireaProject можно сложить в `Lesson7/verification` в отдельную папку с датой. Обязательные два снимка для `FirebaseAuth` оставьте в `res/raw`.
- Для повторного автоматического прогона оставьте запущенным только Pixel 9 Lesson7, выберите **Device Tests Lesson7**, дождитесь завершения и сохраните JUnit XML из `UITests/build/outputs/androidTest-results/connected/debug`. После прогона можно выбрать **Install Lesson7** для повторной установки приложений. Автотесты сетевого фрагмента и формы входа дополняют ручной облачный сценарий из раздела 2.
- В комплект для преподавателя включите проект `Lesson7`, методичку, отчёт, инструкцию по защите и разбор кода. В отчёте укажите дату запуска, устройство, результаты сетевых запросов и действия, выполненные вручную с Firebase. Перед сдачей запустите **Verify Lesson7** ещё раз после добавления снимков в `raw`.
