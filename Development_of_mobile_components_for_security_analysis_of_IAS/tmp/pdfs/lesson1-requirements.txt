ГЛАВА 3. КОМПОНЕНТЫ ЭКРАНА И ИХ СВОЙСТВА Приложения для ОС Android состоит из набора различных экранов. На первом этапе изучения мобильной разработки будут рассмотрены «activity». На запущенном эмуляторе отображается одно «activity» приложения «Layout Type». Как правило одно приложение занимает экран, а пользователь переключается между приложениями с соответствующими экранами. Стоит отметить, что современные версии ОС Android поддерживают возможность разделения экрана на несколько частей, что позволяет в один момент времени отображать несколько «activity». В качестве наиболее простого примера далее рассмотрено почтовое приложение, содержащее несколько «activity» – список писем, просмотр письма и настройки почтового ящика. При работе с приложением производится перемещение по экранам. 
 
Содержимое «activity» формируется из различных компонентов, называемых «view». Самые распространенные «view» – это кнопка, поле ввода, чекбокс и т.д. При разработки пользовательских интерфейсов возможно использовать специальные контейнеры «ViewGroup». Самый распространенный пример «ViewGroup» – это «layout», отвечающий за расположение дочерние элементов на экране (таблицей, строкой, столбцом и т.д.).

ГЛАВА 4. ВИДЫ LAYOUT. КЛЮЧЕВЫЕ ОТЛИЧИЯ И СВОЙСТВА Размещение на экране графических компонентов (кнопки, поля ввода, чекбоксы и т.п.) производится с помощью использования специальных контейнеров. Основное различие заключается в упорядочивании компонентов внутри контейнера. К основным типам макетов «ViewGroup» относятся (рис.4.1): - «LinearLayout» – отображение «View»-элементов в виде одной строки (тип «Horizontal») или одного столбца (тип «Vertical»). - «TableLayout» – отображение элементов в виде таблицы, по строкам и столбцам. - «RelativeLayout» – для каждого элемента настраивается его положение относительно других элементов. - «FrameLayout» – все дочерние элементы прикрепляются к верхнему левому углу экрана. В разметке нельзя определить различное местоположение для дочернего объекта. Последующие дочерние объекты «View» отображаются поверх предыдущих компонентов, частично или полностью затеняя их. - «ConstraintLayout» – размещение элементов «View» путем привязки к дочерним элементам или самому себе.

ГЛАВА 6. ОБРАЩЕНИЕ ИЗ КОДА К ЭЛЕМЕНТАМ ЭКРАНА. ОБРАБОТЧИКИ СОБЫТИЙ. Класс «activity» представляет собой отдельный экран (страницу) или набор экранов приложения. Приложения могут иметь одну «activity», а может и несколько. Каждая отдельная «activity» задает отдельное окно для отображения. Стоит отметить, что современный подход создания мобильных приложений заключается в использовании одного «activity», но с множеством количеством фрагментов или «View». Обращения к элементу на экране из кода производится через связывания его идентификатора. Класс «R» содержит идентификаторы всех ресурсов, расположенных в каталоге «res». Для каждого типа ресурсов в классе «R» создается внутренний класс (например, для всех графических ресурсов из каталога «res/drawable» создается класс R.drawable) и для каждого ресурса данного типа присваивается идентификатор.
